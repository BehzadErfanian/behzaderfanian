# GitHub Growth Roadmap

Last updated: 2026-08-16

## Objective

Build `BehzadErfanian` into an active, credible, technically strong GitHub profile that reflects real engineering work in software, data, AI, industrial systems, and retail technology.

The goal is not to maximize repository count or manufacture a contribution streak. The goal is to build a visible body of original, useful, well-documented engineering work.

## Working rhythm

### Company / daytime focus

Primary focus:

- private Sadr product source code;
- scale communication reliability;
- protocol QA and physical testing;
- release engineering;
- proprietary infrastructure and company-specific work.

Private/proprietary work must remain private and must never be published merely to increase GitHub activity.

### Home / evening focus

Primary focus:

- public engineering projects;
- open-source utilities;
- public documentation;
- GitHub profile quality;
- examples and SDKs;
- public technical writing;
- selected external contributions.

This split is intentional so public work progresses consistently without slowing critical company engineering work.

## Principles

1. **Original work over repository count.**
2. **Useful commits over artificial contribution streaks.**
3. **Documentation is part of the product.**
4. **Every serious public repository should have a clear purpose, README, roadmap, tests where appropriate, and release discipline.**
5. **Never expose private company source, device protocols, credentials, customer data, private keys, packet captures, firmware, or vendor-confidential material.**
6. **Public work may be inspired by production experience, but it must be independently publishable and safe.**
7. **Prefer projects that demonstrate depth: architecture, testing, CI, reliability, documentation, and maintainability.**
8. **External contributions should be genuine: useful issues, documentation fixes, bug reports, tests, or pull requests.**

## Positioning

The public profile should consistently communicate three connected strengths:

- **Software Engineering** — C#, .NET, architecture, testing, integration, release engineering
- **Data & Applied AI** — Python, analytics, data-driven systems, practical AI
- **Industrial & Retail Systems** — embedded/device integration, manufacturing, operational software, POS/ERP integration

## 12-month target

A healthy target for the next 12 months is:

- 4–6 original public repositories worth showing;
- 2–3 flagship projects with real releases;
- a polished profile README and personal site;
- consistent GitHub activity driven by actual project work;
- several meaningful contributions to external repositories;
- at least one reusable public .NET package/tool;
- at least one practical data/AI project;
- at least one technical write-up or reference project based on real engineering lessons without exposing proprietary material.

These are direction targets, not vanity quotas.

## Repository quality standard

A repository intended to represent the profile should normally include, as applicable:

- clear description and topics;
- high-quality README;
- explicit scope;
- installation/usage example;
- tests;
- CI;
- changelog;
- versioning/release policy;
- security notes when relevant;
- issue/PR templates for larger projects;
- screenshots or demo where visual context helps;
- license decision before broad distribution.
